# Подготовка хостовой машины

## Установка WSL

Включение компонентов:
```PowerShell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
```
```PowerShell
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

Перезагрузка:
```PowerShell
Restart-Computer
```

Проверка корректности установки:
```PowerShell
wsl -l -v
```
```
подсистема Windows для Linux не имеет установленных дистрибутивов.
Чтобы устранить эту проблему, установите дистрибутив с инструкциями ниже:

Используйте "wsl.exe --list --online' для перечисления доступных дистрибутивов
и "wsl.exe --install <Distro>" для установки.
```

Для отката изменений:
```PowerShell
dism.exe /online /disable-feature /featurename:Microsoft-Windows-Subsystem-Linux
dism.exe /online /disable-feature /featurename:VirtualMachinePlatform
```

Просмотр списка доступных дистрибутивов:
```PowerShell
wsl --list --online
```

Устанавливаю Ubuntu 24.04:
```PowerShell
wsl --install -d Ubuntu-24.04
```

Задаю root пользователя:
```
zotac:1234
```

Проверяю установку:
```PowerShell
wsl -l -v
```
```
  NAME            STATE           VERSION
* Ubuntu-24.04    Running         2
```

Для удаления дистрибутива:
```PowerShell
wsl --unregister Ubuntu-24.04
```

Запускаю Ubuntu:
```PowerShell
wsl -d Ubuntu-24.04
```

Проверяю пользователя:
```bash
whoami
```
```
zotac
```

# Настройка YC и Terraform

Создаю сервисный аккаунт для Terraform в Yandex Cloud:
```bash
yc iam service-account create --name terraform --description "Service account for Terraform"
```

Проверка:
```bash
yc iam service-account list
```
![](../project/Pasted%20image%2020260726132917.png)

Для удаления сервисного аккаунта:
```bash
yc iam service-account delete --name terraform
```

Назначаю роли сервисному аккаунту:
```bash
yc resource-manager folder add-access-binding \
  --id $(yc config get folder-id) \
  --role editor \
  --service-account-name terraform
```

Для отзыва роли:
```bash
yc resource-manager folder remove-access-binding \
  --id $(yc config get folder-id) \
  --role editor \
  --subject serviceAccount:<account_id>
```

Проверка:
```bash
yc iam service-account list-access-bindings --name terraform
```

Создаю ключ для terraform для аутентификации в Yandex Cloud:
```bash
yc iam key create \
  --service-account-name terraform \
  --output key.json
```

Проверка:
```bash
yc iam key list --service-account-name terraform
```
![](../project/Pasted%20image%2020260726133650.png)

```bash
yc iam key delete --id <id_ключа>
```

## Создание конфигурационных файлов

Создаю файл конфигурации Terraform CLI:
```bash
mkdir -p ~/.terraform.d && nano ~/.terraformrc
```
```yaml
provider_installation {
    network_mirror {
        url = "https://terraform-mirror.yandexcloud.net/"
        include = ["registry.terraform.io/*/*"]
}
    direct {
        exclude = ["registry.terraform.io/*/*"]
    }
}
```

Создаю файл настроек провайдера:
```bash
nano providers.tf
```
```yaml
terraform {
  required_providers {
    yandex = {
      source = "yandex-cloud/yandex"
    }
  }
  required_version = ">= 0.13"
}

provider "yandex" {
  service_account_key_file = "key.json"
  cloud_id  = "b1gmqqn8huu6s39112te"
  folder_id = "b1gk5pe5h3541d01896e"
  zone      = "ru-central1-a"
}
```

Создаю файл переменных:
```bash
nano variables.tf
```
```yaml
variable "cloud_id" {
  description = "Yandex Cloud ID"
  type        = string
}

variable "folder_id" {
  description = "Yandex Cloud Folder ID"
  type        = string
}

variable "zone" {
  description = "Availability zone"
  type        = string
  default     = "ru-central1-a"
}

variable "public_key_path" {
  description = "Path to public SSH key"
  type        = string
  default     = "~/.ssh/id_rsa.pub"
}
```

Создаю файл конфигурации ВМ:
```bash
nano main.tf
```
```yaml
resource "yandex_vpc_network" "default" {
  name = "my-network"
}

resource "yandex_vpc_subnet" "default" {
  name           = "my-subnet"
  zone           = var.zone
  network_id     = yandex_vpc_network.default.id
  v4_cidr_blocks = ["192.168.10.0/24"]
}

data "local_file" "public_key" {
  filename = var.public_key_path
}

data "yandex_compute_image" "ubuntu" {
  family    = "ubuntu-24-04-lts"
  folder_id = "standard-images"
}

# ВМ для PostgreSQL
resource "yandex_compute_instance" "postgresql" {
  name        = "postgresql-vm"
  platform_id = "standard-v3"
  zone        = var.zone

  resources {
    cores  = 4
    memory = 8
  }

  boot_disk {
    initialize_params {
      image_id = data.yandex_compute_image.ubuntu.id
      size     = 50
      type     = "network-ssd"
    }
  }

  network_interface {
    subnet_id = yandex_vpc_subnet.default.id
    nat       = true                    # Публичный IP
  }

  metadata = {
    ssh-keys = "ubuntu:${data.local_file.public_key.content}"
  }
}

# ВМ для ClickHouse
resource "yandex_compute_instance" "clickhouse" {
  name        = "clickhouse-vm"
  platform_id = "standard-v3"
  zone        = var.zone

  resources {
    cores  = 4

  }

  boot_disk {
    initialize_params {
      image_id = data.yandex_compute_image.ubuntu.id

  }

    subnet_id = yandex_vpc_subnet.default.id

    ssh-keys = "ubuntu:${data.local_file.public_key.content}"

}

output "postgresql_ip" {
  value = yandex_compute_instance.postgresql.network_interface.0.nat_ip_address
```

Создаю плейбук для установки postgresql:
```
nano install_postgresql.yml
```
```yaml
---
- name: Install PostgreSQL 17 (packages only)
  hosts: postgresql
  become: yes
  vars:
    pg_version: 17
    pg_repo_mirror: "https://apt.postgresql.org/pub/repos/apt"
  tasks:
    - name: Add PostgreSQL official GPG key
      apt_key:
        url: "https://www.postgresql.org/media/keys/ACCC4CF8.asc"
        state: present

    - name: Add PostgreSQL apt repository (official)
      apt_repository:
        repo: "deb {{ pg_repo_mirror }} {{ ansible_distribution_release }}-pgdg main"
        state: present
        update_cache: yes

    - name: Install PostgreSQL server and contrib
      apt:
        name:
          - "postgresql-{{ pg_version }}"
          - "postgresql-contrib-{{ pg_version }}"
        state: present
        update_cache: yes

    - name: Ensure PostgreSQL is running and enabled
      service:
        name: postgresql
        state: started
        enabled: yes
```

Создаю плейбук для конфигурации postgresql:
```
nano configure_postgresql.yml
```
```yaml
---
- name: Configure PostgreSQL 17 (settings, password, permissions)
  hosts: postgresql
  become: yes
  vars:
    pg_version: 17
    config_flag: "/etc/postgresql/{{ pg_version }}/main/.configured"
  tasks:
    - name: Install acl package (optional but safe)
      apt:
        name: acl
        state: present
        update_cache: yes

    - name: Set listen_addresses to '*'
      lineinfile:
        path: "/etc/postgresql/{{ pg_version }}/main/postgresql.conf"
        regexp: '^#?listen_addresses\s*='
        line: "listen_addresses = '*'"
      notify: restart postgresql

    - name: Allow password authentication from any host
      lineinfile:
        path: "/etc/postgresql/{{ pg_version }}/main/pg_hba.conf"
```

## Запрос 1

Для каждого месяца 2025 года и каждого аэропорта отправления вывести общую выручку от билетов по завершённым рейсам с фактическим временем вылета.  
Результат отсортирован по месяцу и аэропорту отправления.

PostgreSQL:
```SQl
EXPLAIN ANALYZE
SELECT 
    DATE_TRUNC('month', b.book_date) AS month,
    r.departure_airport,
    SUM(b.total_amount) AS revenue
FROM bookings.bookings b
JOIN bookings.tickets t ON b.book_ref = t.book_ref
JOIN bookings.segments s ON t.ticket_no = s.ticket_no
JOIN bookings.flights f ON s.flight_id = f.flight_id
JOIN bookings.routes r ON f.route_no = r.route_no
WHERE DATE_PART('year', b.book_date) = 2025
  AND f.status = 'Arrived'
  AND f.actual_departure IS NOT NULL
GROUP BY month, r.departure_airport
ORDER BY month, r.departure_airport;
```


## Запрос 2

Для каждого маршрута (аэропорт отправления → аэропорт прибытия) выводится:
- количество пассажиров (билетов),
- средняя цена билета,
- средняя задержка вылета (в минутах).
Учитываются только завершённые рейсы (`status = 'Arrived'`) с фактическим временем вылета. Результат отсортирован по убыванию числа пассажиров, показаны топ‑10 маршрутов.

PostgreSQL:
```SQL
EXPLAIN ANALYZE
SELECT 
    r.departure_airport,
    r.arrival_airport,
    COUNT(t.ticket_no) AS passengers,
    AVG(s.price) AS avg_price,
    AVG(EXTRACT(EPOCH FROM (f.actual_departure - f.scheduled_departure)) / 60) AS avg_delay_minutes
FROM bookings.flights f
JOIN bookings.routes r ON f.route_no = r.route_no
JOIN bookings.segments s ON f.flight_id = s.flight_id
JOIN bookings.tickets t ON s.ticket_no = t.ticket_no
WHERE f.status = 'Arrived'
  AND f.actual_departure IS NOT NULL
GROUP BY r.departure_airport, r.arrival_airport
ORDER BY passengers DESC
LIMIT 10;
```

