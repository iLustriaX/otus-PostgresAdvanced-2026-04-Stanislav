# Установка Docker

Обновляю пакеты:
```bash
sudo apt update && sudo apt upgrade -y
```

Устанавливаю docker:
```bash
sudo apt install -y docker.io
```

Добавляю docker в автозагрузку:
```bash
sudo systemctl enable --now docker
```

Добавляю пользователя в группу docker, чтобы не вводить sudo:
```bash
sudo usermod -aG docker $USER
```

`-a` - означает, что группу нужно добавить к списку групп пользователя, а не заменить текущий список.
`-G` - сообщает, чтобы следующий аргумент это имя группы.

Перезахожу в сессию.

Проверка:
```bash
docker run hello-world
```

# Установка kubectl

Скачиваю бинарник:
```bash
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
```

`-L` - следовать HTTP-редиректам.
`-O` - сохранить файл с именем из URL
`-s` - тихий режим. Отобразить только вывод файла stable.txt

Даю права на выполнение и переношу в директорию bin:
```bash
chmod +x kubectl
sudo mv kubectl /usr/local/bin/
```

Проверяю работоспособность:
```bash 
kubectl version --client
```
```
Client Version: v1.36.2
Kustomize Version: v5.8.1
```

# Установка Helm

Скачиваю скрипт установки Helm:
```bash
curl -fsSL -o get_helm.sh https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3
```
`-f` - при ошибке HTTP (например, 404 или 500) `curl` вернёт код ошибки и не создаст файл.
`-S` - (используется вместе с `-s`) — если произошла ошибка, показать сообщение об ошибке (иначе при `-s` вообще ничего не видно). Пара `-sS` — стандартный «тихий, но с ошибками» режим.
`-o` - сохранить результат в указанный файл.

Т.к. не работает из России. Скачиваю через VPN локально и переношу в облако.

# PostgreSQL Deployment + Service

`postgres-deployment.yaml`:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: postgres-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: postgres
  template:
    metadata:
      labels:
        app: postgres
    spec:
      containers:
        - name: postgres
          image: postgres:14
          ports:
            - containerPort: 5432
          env:
            - name: POSTGRES_USER
              value: "testuser"
            - name: POSTGRES_PASSWORD
              value: "testpass123"
            - name: POSTGRES_DB
              value: "testdb"
---
apiVersion: v1
kind: Service
metadata:
  name: postgres-service
spec:
  selector:
    app: postgres
  ports:
    - port: 5432
      targetPort: 5432
  type: ClusterIP
```

Применяю манифест:
```bash
kubectl apply -f postgres-deployment.yaml
```

Жду некоторое время и проверяю запуск пода:
```bash
kubectl get pods
```
```
NAME                                   READY   STATUS    RESTARTS   AGE
postgres-deployment-865d8bb5b4-jhqsq   1/1     Running   0          64s
```

Включаю временный проброс портов на машину:
```bash
kubectl port-forward service/postgres-service 5432:5432 &
```

Выполняю `SELECT` запрос к PostgreSQL в deployment:
```bash
psql -h localhost -p 5432 -U testuser -d testdb -c "SELECT 'Hello from PostgreSQL' AS message;"
```

# Helm чарт

Добавляю репозиторий Bitnami с зеркала yandex:
```bash
helm repo add bitnami https://mirror.yandex.ru/helm/charts.bitnami.com
helm repo update
```

Создаю файл конфигурации `values.yaml`:
```yaml
architecture: replication

auth:
  postgresPassword: "1234"
  username: "appuser"
  password: "1234"
  database: "appdb"
  replicationPassword: "1234"

primary:
  replicaCount: 1
  persistence:
    enabled: false
  resources:
    requests:
      memory: "256Mi"
      cpu: "250m"
    limits:
      memory: "512Mi"
      cpu: "500m"

readReplicas:
  replicaCount: 2
  persistence:
    enabled: false
  resources:
    requests:
      memory: "256Mi"
      cpu: "250m"
    limits:
      memory: "512Mi"
      cpu: "500m"
```

Устанавливаю чарт:
